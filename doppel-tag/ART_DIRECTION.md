# アートディレクションと、それがゲーム設計に与える影響

## 0. 確定した方向性

- キャラクターは**上半身裸のムキムキの男**（全員共通のボディ）
- **ズボンの色・形を選べる**
- **顔は魚から選ぶ**
- 自分のキャラクターは**基本的に後ろ姿しか見えない**
- **常に走っているアニメーション**
- 他プレイヤー／ドッペルが後ろから近づいて**手を伸ばす（肩を掴む）**
- こちらからも後ろから肩を掴める（ドッペル退治コマンド）

---

## 1. この方向性が「買っている」もの

TECH_PLAN.md で挙げた工数の山が、以下のようにほぼ消える。

| 前回の懸念 | この方向性での帰結 |
| --- | --- |
| 6 体分の高精細キャラの描画コスト | ボディ 1 体を全員で共有。描画も制作も 1 体分 |
| コピー実装のためのリグ統一が必要 | 最初から全員同一ボディ＝統一済み |
| 人間の顔を 3 段階変形させるモーフ制作 | 魚頭のモーフ。人体の解剖学的破綻がないので**桁違いに楽**かつ怖い |
| 歩き／走り／しゃがみのブレンドツリー、足 IK | **走りモーション 1 本のみ。**ブレンドツリー不要 |
| 暗所でキャラの見分けがつかない | 魚頭は**シルエットで判別できる**。人間の頭より圧倒的に有利 |
| キャラメイクを許すとコピーが破綻 | 頭（魚）＋ズボン（色・形）の 2 パラメータのみ。コピーは参照差し替え 2 箇所 |

**アニメーションが「走り」と「手を伸ばす」の 2 本で成立する**のが最大の利得。
前回「工数が集中する」と書いた 3 分野（ネットワーク／マップ／アニメーション）のうち、
1 つが丸ごと消えた。

## 2. 「魚の顔」は識別システムそのものである

これは見た目の趣味ではなく、**ゲームの中核システム**として扱うべき。

### 2-1. 必須ルール：1 試合内で魚は重複させない

ロビーで魚の選択を排他にする。同じ魚を 2 人が選べないようにする。

これにより：

- **「同じ魚が 2 匹いる」＝ドッペルの存在が確定**し、しかも**誰がコピーされたかも確定する**
- 推理の土台がルールから自動的に生まれる。追加実装ゼロ
- ボイスチャットで「マグロ、今どこ？」が意味を持つ。呼称が自然に定まる（名前タグ不要）

魚が重複できると、この骨格が丸ごと崩れる。**ここは譲らないこと。**

### 2-2. 魚の選定基準は「かわいさ」ではなく「シルエット」

暗所で影しか見えない場面が多い。**遠景・逆光・シルエットで判別できること**を第一基準に選ぶ。

初期ロスター案（8〜12 種）— 形が互いに衝突しないように選んである：

| 魚 | シルエットの特徴 |
| --- | --- |
| フグ | 完全な球 |
| シュモクザメ | 横に張り出した T 字 |
| チョウチンアンコウ | 前に突き出た提灯（発光する＝暗所で目立つ／隠れられない） |
| ウツボ | 細長く垂れる |
| カレイ | 平たい円盤、目が片側に寄っている |
| マンボウ | 巨大な縦長の円盤 |
| タチウオ | 銀色に光る細い刃 |
| リュウグウノツカイ | 長い赤い背びれが後ろに流れる |
| デメニギス | 透明な頭部、中の目が見える |
| マグロ | 標準形（基準となる「普通の魚」枠） |

チョウチンアンコウのように**自分で光る魚**を入れると、
「隠れられないが仲間からも見つけやすい」という選択の意味が生まれる。
将来的にはこれが実質的なキャラ性能差になるので、バランスを見ながら足すこと。

### 2-3. ズボンは識別に使わない

ドッペルはズボンも完全にコピーする。ズボンは自己表現と、
「細部まで完全に同じ 2 人が並んでいる」という絵の説得力のためにある。

「ズボンだけ微妙に色が違う」という古典的なドッペルゲンガーの手法は魅力的だが、
**それが唯一の判別法になると全員がズボンだけ見るゲームになる**ので採用しない。
やるなら道具（虫眼鏡・懐中電灯）を通したときだけ気づける粗として実装する。

## 3. 「後ろ姿しか見えない」がゲームの統一テーマになる

この作品は結果的に**「背中のゲーム」**になっている。整理すると：

- 自分に見えるのは自分の背中
- 襲撃は背後から来る
- 撃退も背後から行う
- 他人を見るとき、多くの場合その背中を見ている

一本の芯が通っているので、この線から外れる要素は疑ってかかること。
たとえば「正面から使うアイテム」「顔を見せる会話 UI」などはテーマを薄める。

### 3-1. カメラと操作

- カメラは背後固定。**フリールックで首だけ回すのは禁止**（企画の核が死ぬ）
- カメラを回すと**キャラごと回る**（Gorilla Tag や旧来の TPS 方式）
- 回転速度に上限をかける

### 3-2. 「振り返る」を最重要の操作にする

**背後を確認する専用アクションを 1 つ作ること。** このゲームで最も重要なボタンになる。

推奨仕様：ボタン長押しでカメラだけが後方を向く。その間、

- 前進速度が落ちる（例：0.6 倍）
- 視野角が狭まる
- 進行方向は見えない（前の壁にぶつかる、アイテムを見落とす）

**「後ろを見る＝前に進めない」**というトレードオフが、このゲームの毎秒の判断になる。
ここのコストとリターンの調整が、遊びの質をほぼ決める。最優先で詰めること。

### 3-3. 鏡は「唯一、正面が見られる場所」になる

自分の顔を一度も見ないゲームなので、鏡が特権的な意味を持つ。
マップに固定設置し、数を絞ること。

- 自分の正面を初めて見る場所
- ドッペルは映らない／二重に映る（確定判定）
- **すでに掴まれている自分の顔が、思ったより崩れている**——という無料の恐怖演出

## 4. 「常に走っている」の解釈と、その帰結

2 通りの解釈がある。どちらを採るかで別のゲームになるので明示的に決めること。

### 解釈 A（推奨）：見た目だけ常に走っている

止まっていても脚が空回りする。移動速度は別パラメータで制御する。

- 実装が最も単純。アニメーションはループ 1 本
- 見た目がコミカルになり、ホラーとのギャップが作品の個性になる
- **重要な副次効果：姿勢から意図が読めない。**
  普通のゲームでは忍び寄る相手は動きが変わるが、この作品では全員が常に同じ動き。
  企画にあった「ドッペルが探索している素振りをする」が**アニメーション面から無料で成立する**

### 解釈 B：本当に止まれない

常時強制的に前進し続ける。鬼ごっこの純度は上がるが、探索・アイテム収集と噛み合わない。
採るなら「立ち止まれるのは特定の安全地帯だけ」など別の設計が要る。

**推奨は A。** ただし足音は**アニメーションではなく実移動速度に紐づける**こと。
そうしないと止まっていても足音が鳴り続け、音による索敵が全部壊れる。

## 5. アニメーションの必要セット（全 5 本）

| アニメーション | 用途 | 備考 |
| --- | --- | --- |
| 走り（ループ） | 全ての移動・待機 | 全キャラ共通、1 本のみ |
| 手を伸ばす（上半身レイヤー） | 掴み・撃退の**両方** | 走りに重ねる。下半身は走りのまま |
| 掴まれて振り返る | 被襲撃演出 | 0.8〜1.2 秒のカメラ演出。ここだけ作り込む |
| 死亡／連れ去り | 決着 | 1 本 |
| 勝利 | リザルト | 任意 |

### 5-1. 掴みモーションは、ドッペルとプレイヤーで絶対に共通にすること

これがこの作品で最も重要な設計判断のひとつ。

攻撃（ドッペルが襲う）と撃退（プレイヤーが退治する）は**同じ動作**であり、
アニメーションも同一にする。すると：

- 遠くから見ている第三者には、**それが襲撃なのか救助なのか判別できない**
- 誰かに手を伸ばした瞬間、**自分がドッペルに見える**
- ボイスチャットで「今マグロがフグに手を伸ばした！」「違う、俺は退治しようとしたんだ！」
  という叫び合いが自然に発生する

前回のレビューで「対称メカニクスが企画の核」と書いたが、
この見た目の統一によってそれが**観測者のレベルまで貫徹される**。ここが最大の見せ場になる。

### 5-2. 魚には首がない

人間の頭は 180 度回らないが、魚の頭ならいくらでも回る。
これは**ボーンを 1 本余分に回すだけで成立する、極めて安いホラー演出**。

- 掴まれて振り返るとき、体はそのままで頭だけが完全に 180 度回る
- **ドッペルが前を向いて走りながら、頭だけ後ろを向いてこちらを見ている**
  ——この一枚絵はこの作品の看板になりうる。コストはボーン回転のみ

## 6. 醜悪化（3 段階）の設計

魚頭なので、変形の方向性が明確に定まる：**深海魚化。**

| 段階 | 状態 | 見た目 |
| --- | --- | --- |
| 0 | 通常 | 選択した魚そのまま。目に光沢、色が鮮やか |
| 1 | 一度掴まれた | 膨張、目が白濁、口が開き歯が伸びる、体色が抜ける |
| 2 | 二度掴まれた | 顎が裂ける、目が飛び出す、皮膚が透ける、発光器官が生える |
| 3 | 三度目＝死 | 完全な深海の異形。元の魚の面影だけが残る |

- 元の魚の**配色だけは保つ**こと。「あれは元マグロだ」と分かるからこそ怖い
- ボディ（ムキムキの上半身）は**一切変えない**。
  完璧に正常な肉体の上に、崩れていく魚頭が乗っている、というギャップが本作の絵の芯
- モーフは魚ごとに作る必要があるが、変形の「方向」は共通なので 1 種作れば要領が掴める

## 7. トーンについての判断

上半身裸の筋肉質な男＋魚頭は、**コメディホラー**の領域に入る。真面目なホラーにはならない。

これは弱点ではなく、現在最も勝ち筋のあるジャンル
（Lethal Company / Content Warning / Devour / Gorilla Tag はいずれもこの領域）。
配信映えし、クリップが拡散しやすい。**この路線を狙うと明示的に決めること。**

ただし注意が 2 点：

1. **笑いの賞味期限は 10 分。**魚頭マッチョは初見で爆笑されるが、その後は日常になる。
   笑いが切れた後に残るのが「背後の取り合い」の緊張であり、
   だからこそ Phase 1（グレーボックスで掴み合いだけを検証する）が決定的に重要になる。
   **アートで面白さを判定してはいけない**
2. ストアページと宣伝はコメディ寄りに振る一方、**ゲーム内は真面目に怖く作る**。
   ギャップが商品価値になる。ふざけた見た目のまま演出まで軽くすると、ただのネタゲーになる

## 9. 追加で決めるべきこと

1. 走り続ける見た目に対し、**しゃがみ／忍び足**を入れるか。
   入れるなら「走りモーションのまま低い姿勢」にすればアニメーション 1 本追加で済み、
   コミカルさも増す
2. 魚の**選択が性能に影響するか**（チョウチンアンコウは光る＝隠れられない等）。
   影響させるなら、それはもうキャラ選択であり、バランス調整の対象になる
3. 自分がコピーされたとき、**本人に通知するか**。
   通知しない方が怖いが、「自分の姿が走っているのを見る」という最高の瞬間を
   確実に発生させたいなら、コピー対象は視界内で決定する、という手もある
4. 声。魚頭から人間の声が出るのか、魚の鳴き声的な加工をかけるのか。
   近接ボイスチャットを使う以上、加工の有無は識別性に直結する
