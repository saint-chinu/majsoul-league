# ブラウザゲーム（PC 含む）として作る

## 0. 結論

**可能。というより、本作とはかなり相性が良い。**

前回 PLATFORM_AND_STACK.md では「JS は性能ではなく**出口**の問題で選ばない」と書いた。
出口がスマホアプリだったからで、**出口がブラウザ自体になるなら、その理由は消える。**

ただし 1 点だけ明確に不利になるところがある（3 章：収益化）。

---

## 1. ブラウザが本作に有利な理由

### 1-1. ボイスチャットが無料で、しかも標準機能で作れる

これが最大の利点。本作の設計はボイスチャットに深く依存している。

ネイティブアプリなら Vivox / Agora / Photon Voice といった外部サービスが必要で、
権限・課金・SDK 統合の面倒がついて回る。**ブラウザには全部標準で入っている。**

| 必要な機能 | ブラウザでの実現 |
| --- | --- |
| マイク取得 | `getUserMedia`（標準） |
| P2P 音声通話 | **WebRTC**（標準）。サーバ費用ゼロ |
| **距離減衰・空間音響** | **Web Audio の `PannerNode`**（標準）。3D 位置から鳴らせる |
| 壁越しのこもり | `BiquadFilterNode` のローパス（標準） |
| **AI による声の録音再生** | 音声ストリームをそのままバッファできる。**加工も標準機能** |

AI_DESIGN.md 3-4 で提案した「**プレイヤーの声を 10 秒バッファし、歪ませて AI の位置から再生する**」
——本作最大の恐怖演出になるはずの仕組みが、**ブラウザなら追加コストほぼゼロで実装できる。**
ピッチ変更もリバーブも Web Audio の標準ノードで組める。

**この一点だけでもブラウザを選ぶ価値がある。**

### 1-2. 配布が URL

協力ゲームにとって、**「このリンク踏んで」で全員が集合できる**のは決定的に強い。
インストールなし、ストアなし、アカウント作成なし、バージョン違いによる非互換なし。

部屋番号か URL パラメータで合流できるようにすれば、
COST_AND_SOLO.md で挙げた「一緒に遊ぶ相手を集める手段が生命線」という課題が、
最も軽い形で解決する。

### 1-3. 必要な性能が低い

本作は 3D ゲームとしては極端に軽い。

- キャラは 2D スプライト 6 枚（板ポリ）
- マップは 1 つ、狭くて暗い（描画範囲が小さい）
- 物理はほぼ不要（移動と衝突だけ）
- **通信も軽い**：常時走り、照準なし、飛び道具なし。**15〜20Hz のサーバ更新で足りる**

WebGL2 で余裕を持って動く。ブラウザの性能上限が問題になる企画ではない。

### 1-4. 遅延を吸収する設計が既に入っている

- 掴みの 0.3〜0.4 秒の予備動作
- 判定が「表示中のスプライト帯」という整数（浮動小数の巻き戻し判定が不要）
- 掴まれた瞬間の 1 秒の振り返り演出

**ブラウザの WebSocket 経由（TCP）でも成立する設計に、既になっている。**

### 1-5. チート対策が不要

ブラウザゲームはメモリもコードも丸見えで、本来ならチートし放題。
だが**本作は PvE 協力**なので、そもそも守るべき秘密がない。
AI の正体を覗かれても、対戦相手が得をしない。**PvE 化の恩恵がここでも効いている。**

## 2. 技術選定：2 つの道

### 道 A：three.js（TypeScript）でウェブネイティブに作る

**ブラウザ体験としては最良。**

- 起動が速い（数百 KB〜数 MB）。リンクを踏んで数秒で遊べる
- WebRTC・Web Audio をそのまま使えるので、1-1 の利点を最大限に取れる
- 暗いダンジョン＋懐中電灯（`SpotLight` ＋シャドウマップ）は普通にできる
- **ノーマルマップ付きの板ポリ**にすれば、スプライトが懐中電灯で正しく陰影を持つ
  （SPRITE_PIPELINE.md 7 章の要件を満たせる）

**代償：エディタがない。** レベルは Blender で作って glTF で読み込む。
物理、キャラクターコントローラ、ネットコード、UI——全部自分で書くか、
ライブラリを組み合わせることになる。**プログラミングの比重が大きい。**

対抗：**PlayCanvas**（ウェブ特化でエディタあり）、**Babylon.js**（機能が厚い）。
エディタが欲しいなら PlayCanvas は有力。

### 道 B：Unity の WebGL 書き出し

**エディタが使え、将来スマホやSteamへ持っていける。**

- COST_AND_SOLO.md / PLATFORM_AND_STACK.md の計画をそのまま使える
- 物理・キャラコン・アセットストアの恩恵がある
- **1 つのプロジェクトでブラウザ・PC・スマホ全部に出せる**

**代償：**

- ビルドが大きく、**初回読み込みに数十秒**かかる。「リンクを踏んですぐ」にはならない
- モバイルブラウザは公式には非対応扱い
- WebRTC やマイクを使うのに JS 側との橋渡し（jslib）が必要で、1-1 の利点が目減りする
- スレッドを使うなら配信サーバに COOP/COEP ヘッダの設定が要る

### 判断基準

| 条件 | 選ぶべき道 |
| --- | --- |
| **ブラウザ版が製品そのもの**（サイトや itch.io で公開して遊んでもらう） | **道 A（three.js）** |
| ブラウザ版はテスト用で、本命はスマホ／Steam | **道 B（Unity）** |
| プログラミングが得意で、全部自分で組むのが苦でない | 道 A |
| エディタやアセットストアの助けが欲しい | 道 B（または PlayCanvas） |

**「スマホは今後でいい」なら、当面ブラウザが製品になる。その前提なら道 A を推す。**
1-1 のボイス周りの利点が、本作にとって特に大きいため。

ただし**プログラミング経験が浅いなら道 B**。three.js は自由だが、
自由とは「全部自分で書く」という意味でもある。

## 3. 唯一はっきり不利な点：収益化

> **詳細は [MONETIZATION.md](MONETIZATION.md) に分離した。**
> 要点：協力ゲームは入口に課金を置くと「このリンク踏んで」という最大の武器を失うので、
> **無料開放を推す。**有料にするなら「部屋を立てる人だけ有料」の形が最も無理がない。


ブラウザゲームは、ストアに比べて売るのが難しい。

| 手段 | 評価 |
| --- | --- |
| ブラウザで無料公開 → **Steam で有料版**を売る | **最も現実的。**ブラウザ版が体験版と宣伝を兼ねる |
| Poki / CrazyGames などのポータルで公開 | 収益分配あり。集客も担ってくれるが、内容の制約もある |
| itch.io で公開（投げ銭・有料設定も可） | 手軽。同人的な規模なら十分 |
| 広告 | 本作の没入感とは相性が悪い |
| 直接課金（Stripe 等） | 実装は可能だが、集客を全部自分で持つことになる |

**推奨：ブラウザ版を無料で出して人を集め、本気で売る段階で Steam 版を作る。**
Unity なら移植が楽（道 B の利点）。three.js なら Electron / Tauri で包む手もあるが、
Steam で売るなら作り直しに近くなる可能性は見ておくこと。

## 4. 実装上の要点（ブラウザ固有）

| 項目 | 注意 |
| --- | --- |
| **ビルボード** | `THREE.Sprite` は**常にカメラを向く**ので使わない（SPRITE_PIPELINE.md 1 章）。板ポリを **Y 軸だけ**回して使う |
| **スプライトのライティング** | `MeshStandardMaterial` ＋ `normalMap` ＋ `alphaTest`。懐中電灯で正しく陰影が出る |
| **深度ソート** | アルファブレンドではなく `alphaTest`（クリップ）。壁との前後関係が正しくなる |
| **ホストをブラウザにしない** | **ブラウザは非アクティブなタブを激しく制限する。**ホストのタブが裏に回るとゲームが止まる。**小さな権威サーバ（Node）を立てること** |
| ゲーム通信 | WebSocket で 15〜20Hz。本作の速度なら十分。WebRTC DataChannel は必要になってから |
| **音声通話** | WebRTC の P2P。**サーバ費用ゼロ**。ただし NAT 越えできない環境用に TURN の用意が要る |
| 音の開始 | ブラウザはユーザー操作なしに音を鳴らせない。「クリックして開始」を必ず挟む |
| カメラ操作 | Pointer Lock を使う（クリックで取得、Esc で解除）。解除時の挙動を設計しておく |
| テクスチャ | アトラスにまとめ、KTX2 / Basis で圧縮。初回読み込み時間に直結する |
| 描画 API | **WebGL2 を前提に**。WebGPU は対応環境がまだ揃わない |

## 5. 運用費

| 項目 | 費用 |
| --- | --- |
| 静的ファイルの配信 | **無料**（Cloudflare Pages / GitHub Pages / Netlify） |
| ゲームサーバ（Node） | 小さな VPS で月 700 円程度。無料枠のあるサービスもある |
| 音声（WebRTC P2P） | **無料** |
| TURN サーバ（NAT 越え用） | 同じ VPS に coturn を同居させれば追加費用なし |
| ドメイン | 年 1,500 円程度 |

**月 1,000 円以下で運用できる。**COST_AND_SOLO.md の「実質ゼロ円」という結論は変わらない。
