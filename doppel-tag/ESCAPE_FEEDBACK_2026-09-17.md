# 試遊フィードバック（2026-09-17）— 脱出モードの 5 つの変更仕様

制作者の試遊で出た 5 点を、そのまま実装に渡せる仕様にした。
対象は現行の脱出モード（1階・2階・地下・地上の 4 階層、梯子 → 柱 → 暗号錠 → 地下鍵扉 → 地上）。

「現状」は配信バンドル（`escape-map` / `simulation` / `ceiling` / `renderer`）から読んだ事実。
サーバー側の挙動で断定できないものは「要コード確認」と書いた。

| # | 制作者の指摘 | 変更の要点 |
|---|---|---|
| 1 | 梯子を設置したのに「階段を上がる」のはおかしい | 梯子を掛けた場所は**梯子を登る**。文言・見た目・音を梯子に統一 |
| 2 | 地上で「調べる」を押さないと脱出できないのはおかしい | 出口は**歩いて通過するだけ**で脱出（階段の移動と同じ扱い） |
| 3 | 地下でドッペルが 1 体増え、撃退してもクールタイム無しで画面外から即復活 | 撃退後は**必ず待ち時間**を置き、補充も待ち時間と最小距離を守る |
| 4 | 地上は一本道にして、上からドッペルが降ってくる（3 体くらい） | 地上を**幅 3 マスの直線通路**にし、進行に応じて**3 回の天井落下** |
| 5 | ゴールしたら未ゴール者の画面になる。ゴール感のある立ち絵を出してほしい | 脱出した本人には**脱出の立ち絵**を出し、観戦は任意 |
| 6 | マップが前後左右逆 | 施設図を**カメラの向きが上**になるよう回転し、自分の向きを扇形で描く（北固定は切替可） |
| 7 | マップのオブジェクトが説明なくて意味不明 | 拡大図では**すべての印に名前**を付け、形を種類ごとに分け、凡例を出す |

## 1. 梯子を掛けた場所は「梯子を登る」

### 現状

- 任務 `barricade`：「崩れた階段に梯子を設置」（1階 (12,6)、5 秒）
- 設置後に開く移動先 `up`：名前が **「2階へ上がる」**、案内が「調べる / 移動」
- 設置後、`renderer` が (12,4) に梯子のモデルを**斜めに立て掛けて**描画する
- 戻りの `down`：「1階へ戻る」

つまり見た目は梯子なのに、文言は階段で、移動の演出も階段と同じ。

### 仕様

| 項目 | 変更後 |
|---|---|
| 任務名 | 「崩れた階段に梯子を掛ける」 |
| 任務リスト | 「崩れた階段を上る方法を探す」→「梯子を掛ければ上れそうだ」／「崩れた階段に梯子を掛ける」 |
| `up` の名前 | **「梯子で 2 階へ登る」** |
| `down` の名前 | **「梯子で 1 階へ降りる」** |
| 移動の演出 | 階段の移動より **0.4 秒長く**（登る時間）。その間、画面を軽く上へパン |
| 音 | `ladder-climb`（金属の段を 3 回踏む音、約 1.2 秒）。既存の足音とは別 |
| 梯子の見た目 | 設置前：崩れた段と、上に届かない高さの瓦礫。設置後：梯子が**崩れた段の上端まで届いている**ことが一目で分かる長さ |
| 1 階側の梯子の位置 | (12,4) の描画位置を **移動先 `up` の入口 (12,2) の真上**に寄せる。「梯子の根元に入ると登る」が自明になる |

**変えないもの**：梯子は 1 本で、掛けたら 1 階側と 2 階側の両方から使える（現状どおり）。

### 実装箇所

- `escape-map`：`P`（移動先）の `name`、`F`（任務）の `name`、`w`（任務リスト）の文言
- `renderer`：梯子モデルの位置と、移動先ラベル `u(o.from, o.name, …)` の案内文
- `soundscape`：`ladder-climb` の追加。移動先の `id === "up" || "down"` のときだけ鳴らす

### 確認

- 梯子を掛けた直後、1 階の梯子の根元に歩いて入ると「梯子で 2 階へ登る」と表示され、登る音が鳴って 2 階に着く
- 2 階から降りるときも同じ（音は同じでよい）
- 任務リストに「階段を上る」という文言が残っていない

## 2. 出口は歩いて通過するだけで脱出

### 現状

- 地上の出口 (12,8) で、2 m 以内に入り **「調べる」を押す**と脱出（案内「門の外へ脱出する ／ 調べる / F」）
- 階段（`up` / `down` / `basement` / `back1` / `surface`）は**歩いて入るだけ**で移動する

同じ「通路の先へ進む」なのに、出口だけ操作が要る。追われながら門に着いて、ボタンを探して掴まれるのは理不尽に感じる。

### 仕様

| 項目 | 変更後 |
|---|---|
| 判定 | 出口の**通過線**（4 章の一本道の終端、幅 3 マス）を**跨いだ瞬間**に脱出。ボタン不要 |
| 呪い中 | 呪われた人も**通過できる**（ESCAPE_AND_CURSE 1-6「呪われた人は出口を通れない」は**採用しない**。本作の地上は「走り抜ける」場面であり、門の前で待つ設計ではない） |
| 二次呪い中 | 同じく通過できる（現行の手引きどおり） |
| 演出 | 通過した瞬間に画面が白く抜け、5 章の立ち絵へ |
| 案内 | 門が見えた時点で HUD に「門を抜けろ」。ボタン表記は出さない |
| 誤通過 | 一本道の終端なので、意図せず通過することはない。**取り消しは無い** |

### 実装箇所

- `escape-map`：出口 `R` を「点＋調べる」から「線分」に変える（`exitLine: { floor: 4, z: 8, x0: 11, x1: 13 }` のような定義）
- サーバーの `afterPlayers`（脱出判定）：位置の更新後に、前フレームと今フレームで `z` が通過線を跨いだら `escapedAt` を付ける（**1 フレームで跨ぎ切る速度でも取りこぼさない**ため、点ではなく線で判定する）
- クライアント `pe()`：`"門の外へ脱出する"` の分岐を削除

### 確認

- 走ったまま門を抜けると、ボタンを押さずに脱出扱いになる
- 呪われたまま門を抜けても脱出できる。追ってきたドッペルは門の手前で止まる（門の外には出ない）
- 門の 2 m 手前で立ち止まっても脱出にならない

## 3. 地下の追加ドッペルと「即復活」

### 現状（推定。要コード確認）

共有シミュレーションの補充ルールはこうなっている。

```
目標数 t = 人数 ≥ 5 なら 2、それ以外 1
毎 tick： 生存ドッペル数 + 復帰待ち数 < t なら、即座に spawnDoppel()、次回は 12 秒後
撃退時： 復帰待ちに登録（仲間が撃退：20 秒、コピー元本人が撃退：50 秒）
```

地下に入ると 1 体増える、という観察から、**サーバーは地下で目標数 t を +1 している**と考えられる。
そのとき起きること：

1. 地下に入った tick で「生存 1 ＋ 復帰待ち 0 ＜ 2」→ **即座に 1 体出現**（これが「1 体増えた」）
2. 1 体を撃退 → 復帰待ち 1。しかし「生存 1 ＋ 復帰待ち 1 ＜ 2」は成り立たないので補充されない……はずだが、
   **2 体とも撃退した場合**や、**撃退した個体が復帰待ちに登録されない経路**（例：地下用の追加分が `returns` を経由しない）があると、
   「生存 0 ＋ 復帰待ち 1 ＜ 2」→ **撃退した直後に新しい 1 体が即出現**する
3. 出現位置は `hiddenSpawn`：**全員から 11 m 以上離れ、誰の視線にも入らない床**。地下は一本の長い回廊なので、
   「11 m 先の角の向こう」が最短で選ばれる。**撃退した 2 秒後に角から同じ姿が歩いてくる**ように見える

つまり「クールタイム無し」は撃退個体の復帰ではなく、**補充スポナーが撃退直後に穴を埋めている**可能性が高い。

### 仕様

| 項目 | 変更後 |
|---|---|
| 撃退後の補充禁止 | **どの経路の撃退でも**、その部屋の補充スポナーを **20 秒間停止**する（`nextSpawn = max(nextSpawn, time + 20)`）。コピー元本人の撃退なら 50 秒 |
| 目標数の増加 | 階層で目標数を上げるとき、**即時出現ではなく「復帰待ち」として登録**する（`returns.push({ at: time + 15 })`）。地下に降りて 15 秒は増えない |
| 地下の目標数 | 人数 ≤ 4：**2**、人数 ≥ 5：**3**（現行の +1 を維持。ただし上の 2 行を守る） |
| 最小距離 | 補充・復帰の出現位置は、全員から **18 m 以上**（現行 11 m）。加えて、**最も近い探索者との経路長が 25 m 以上**（角 1 つでは足りない） |
| 出現の告知 | 出現の 3 秒前に「どこかで不穏な気配がする…」を出す（現行は出現と同時） |
| 復帰個体の姿 | 撃退された個体が戻るときは**別の仲間の姿**（現行どおり）。ただし「今いる階層にいる仲間」からだけ選ぶ |

### 実装箇所

- サーバーの階層別スポーン（`afterPlayers` か `tick` のオーバーライド）。**要コード確認**：地下用の追加分が `returns` を通っているか、撃退時に `nextSpawn` を延ばしているか
- `hiddenSpawn`：距離 11 → 18、経路長条件の追加（`findPath` の結果の長さを使う。既に逃走時の出現で同じ計算をしている）
- `spawnDoppel` の候補（`h`）を同じ階層の仲間に絞る

### 確認

- 地下に降りた直後 15 秒間はドッペルの数が増えない
- 地下でドッペルを撃退したあと、**20 秒間**は新しい個体が現れない（画面に出るのも、気配の通知も）
- 出現したとき、最も近い探索者から歩いて 25 m 以上離れている
- 上記を「仲間が撃退」「本人が撃退」「2 体連続で撃退」の 3 通りで確認

## 4. 地上は一本道、上から 3 体降ってくる

### 現状

地上（階層 4）は他の階と同じ**環状回廊＋十字＋中央の広間（9×14 マス）**。着地点 (12,20) から出口 (12,8) まで直線 12 マス（約 29 m）だが、広間なので四方から来る。

天井落下は「**呪われた本人が孤立し、敵を 1.5 秒見失い、3 秒以上走っている**」ときだけ 30% で起きる仕組みで、地上では狙って起こせない。

### 仕様：地形

```
地上（階層 4）、28×27 マスのうち使うのは以下だけ。他は壁。

  x = 11..13（幅 3 マス ＝ 7.2 m）、z = 22..6 の直線通路（長さ 17 マス ＝ 41 m）
  z = 22：地下からの着地点（現行 (12,20) を (12,22) へ）
  z = 6 ：出口の通過線（2 章）。その先 z = 5..3 は「門の外」（描画のみ、進入不可）
  途中に遮蔽物なし。曲がり角なし。分岐なし。扉なし。
```

- **幅 3 マスの理由**：ドッペルが正面を向いて降りてきても、**左右 1 マス分の回り込み**ができる。幅 1 だと背後を取れず、幅 5 だと避けるだけになる
- 天井は他の階より高く見せる（落下の予兆として、上に空間があることを見せる）
- 照明：通路の両端だけ明るく、中間は暗い。出口の光が「あそこまで走れ」の目印

### 仕様：落下

| 項目 | 値 |
|---|---|
| 発動 | **先頭の探索者**が通過線 z = 18、z = 14、z = 10 を跨いだとき（3 回） |
| 落下位置 | 先頭の探索者の **5〜7 m 前方**（現行の `minRange` / `maxRange` と同じ）、通路の中央列 x = 12 |
| 落下の向き | 1 回目：**出口向き（探索者に背を向けて着地）**。2・3 回目：**探索者向き** |
| 着地の演出 | 現行の 6 段階（落下 0.55 → 伏せ 1.0 → 顔上げ 0.5 → 起き上がり 0.65 → 立ち 0.35 → 構え 0.25、合計 3.3 秒）そのまま |
| 落下中の掴み | 現行どおり不可（0.55 秒）。**着地後は誰でも背後から掴める**（現行の「本人だけ」の例外は地上でも維持） |
| 落下後の行動 | 最も近い探索者を追う。**擬態・徘徊はしない**（地上に着いた時点で正体は明らかなので） |
| 同時数の上限 | **3 体**。撃退された個体は**復帰しない**（地上には補充スポナーを置かない） |
| 姿 | それぞれ別の仲間の姿。3 体とも違う魚 |
| 前触れ | 落下の 0.8 秒前に、真上から `ceiling-scrape`（現行の音）。**音の位置は落下地点** |
| 通知 | 「天井が軋む」を落下地点の方向矢印つきで 1 秒 |

**3 体で足りるか**：通路 41 m を歩き 2.3 m/s で約 18 秒。3.3 秒の着地演出が 3 回で約 10 秒。
先頭は演出中に横をすり抜けられ、後続は起き上がった個体に追われる。**先頭が抜けて後続が捕まる**構図が自然にできる。
足りなければ落下位置を「先頭ではなく**最後尾**の 5〜7 m 前方」に変えると、後続への圧力が上がる。数は 3 のまま試す。

### 撃退の意味

地上は「走り抜ける」場面だが、掴みは残す。**着地後 3.3 秒は背後を取れる**ので、
仲間が先に進んだ個体を背後から消せば、後続が安全に通れる。「先に行った人が道を作る」協力。

### 実装箇所

- `escape-map`：階層 4 の生成（`E()` の `o === 4` 分岐）を直線通路に差し替え。`P`（`surface` の着地点）と出口を移動
- サーバー：`resolveCeilingDrops` とは**別の**トリガー（通過線ベース）で `startCeilingDrop(敵, 対象, 位置)` を呼ぶ。`startCeilingDrop` 自体は流用できる（状態の初期化が揃っている）
- `ceilingCandidates`：通路上の落下点は固定なので、候補計算は不要。位置を直接渡す
- 地上の敵の `deceive` / `wander` を無効化（`state = "chase"` 固定）
- `renderer`：階層 4 の天井の高さ、両端の照明

### 確認

- 地上に着いてから出口まで、曲がり角も分岐も無い
- z = 18 / 14 / 10 を先頭が跨ぐたびに、前方 5〜7 m に 1 体降ってくる（合計 3 体、それ以上は出ない）
- 1 体目は背を向けて着地し、着地後に背後から掴んで撃退できる。撃退した個体は戻らない
- 3 体すべてを撃退しても補充されない
- 6 人で走ったとき、先頭は演出中にすり抜けられ、最後尾が追われる

## 5. 脱出した本人には「脱出の立ち絵」

### 現状

出口を通った人は `escapedAt` が付き、HUD に「脱出しました · 残った仲間を観戦中」。
カメラは**残っている仲間**（生存者の先頭）に移り、その人が呪われれば呪いの演出まで見える。
チーム欄では「脱出」と表示される。

達成感が無いまま、他人の恐怖を見せられる。「勝った」感覚が出ない。

### 仕様

| 段階 | 内容 |
|---|---|
| 通過の瞬間 | 画面が 0.3 秒で白く抜ける。`escape-1`（門を抜ける風の音＋遠くの鳥）を鳴らす |
| **立ち絵** | 白から **1.0 秒**で立ち絵へ。夜明け前の空（藍 → 橙のグラデーション）、門のシルエット、**自分の魚頭の正面〜斜め前**の立ち絵（胸から上、画面の 6 割）。顔は `hits` に応じた段階（1 回・2 回掴まれていれば少し変貌したまま）。**初めて自分の顔を正面から見る場面**にする |
| 見出し | 「脱出、生還。」（現行の勝利画面の文言を流用） |
| 副文 | 「残り {n} 人が施設の中にいる」。人数は 1 秒ごとに更新。全員が出るか脱落したら「夜が、明ける。」に変わる |
| 滞在 | 試合が終わるまで**この画面のまま**。ゲーム画面には戻らない |
| 観戦 | 画面下に **「仲間を見守る」** ボタン。押した人だけ現行の観戦（カメラが仲間に移る）へ。観戦中は右上に「立ち絵に戻る」 |
| 音 | BGM を脱出用の静かなものへ切り替え、施設内の足音・悲鳴は**鳴らさない**（観戦を選んだ場合のみ鳴らす） |
| チーム欄 | 立ち絵の右下に小さく残す（誰が呪われているかは見える。安全な場所から仲間を案じる） |
| 試合終了 | 現行のリザルトへ。立ち絵はリザルトの背景として残す |

### 立ち絵の素材

- 魚 6 種 × 顔の段階 4（無傷・1 回・2 回・3 回目は脱落なので不要 → **3 段階**）＝ **18 枚**。
  ただし SPRITE_PIPELINE の**レイヤー分離**（肉体は共通、頭だけ差し替え）で作れば **肉体 1 ＋ 頭 18**
- 1024×1024、WebP。ズボンの色は既存のパレット置換で反映
- 背景（空・門）は 1 枚。共通
- 既存の `character-art` の正面スプライトを拡大して仮に使い、**仮絵で先に動作を確認**してから本絵を発注する

### 実装箇所

- クライアント `y.onWorld` / `Yt`：`i.escapedAt !== undefined` の分岐で、観戦への切り替えの代わりに `escape-scene` を表示
- `equipment`（演出用 canvas）に `escaped` の描画を追加。既存の `won` の演出（放射状の光と文字）が骨格として流用できる
- `renderer`：観戦は「仲間を見守る」を押したときだけ `o = h ?? u[0]` の追従に入る
- `soundscape`：脱出後の音のフィルタ

### 確認

- 門を抜けた瞬間に白く抜け、1 秒後に自分の魚頭の立ち絵が出る。カメラが勝手に仲間へ移らない
- 立ち絵の顔が、掴まれた回数に応じて変わっている
- 「仲間を見守る」を押すと観戦できる。押さなければ試合終了まで立ち絵のまま
- 全員が出るか脱落した瞬間に副文が「夜が、明ける。」になり、その後リザルトに進む

## 6. 施設図の向き — カメラの向きを上にする

### 現状

- 施設図（右上の小図と、`M` の拡大図）は**北固定**。世界の +z が画面の下、+x が右。地形と 3D の対応自体は正しい（鏡像にはなっていない。確認済み）
- 脱出モードの図では、自分は**向きの無い点**で描かれる（お札モードの図にはあった三角形が無い）
- カメラは「左右ゆっくり・角は素早く」「前後追随・水平固定」の既定モードで**通路の向き（`corridorHeading`）**を向き、`W` はその向きへ進む。つまりプレイヤーにとっての「前」はカメラの向きであって、図の上ではない

開始地点では上を向いているので最初は合っているが、**一度でも画面の下方向を向くと、図の上が「後ろ」、右が「左」になる。**
向きの印が無いので、自分が今どちらを向いているかも図からは分からない。制作者の「前後左右逆」はこの状態。

### 仕様

| 項目 | 変更後 |
|---|---|
| 回転 | 小図・拡大図とも、**カメラの向き（`corridorHeading`）が画面の上**になるよう、自分の位置を中心に回転する（カーナビ方式）。canvas なら `translate(自分) → rotate(heading + π) → translate(-自分)` で世界 +z が下・+x が右の現在の描き方のまま向きだけ変わる |
| 自分の印 | 中心に**扇形（開き 60°、長さ 4 マス分）**でカメラの向きを描く。身体の向き（`yaw`）がカメラと違うときは、小さな三角形で身体の向きも重ねる（後方確認中・鏡中に分かる） |
| 回転の追従 | カメラが角で回るとき、図も同じ速さで回す（急回転しない。0.25 秒で追従） |
| 北固定 | 拡大図の見出しに **「北固定」切替**。切替は `localStorage` に保存。北固定のときは図の隅に「N」を出す |
| 文字 | 回転しても**文字は常に正立**（各ラベルの描画時に逆回転する） |
| 範囲 | 小図は自分を中心に半径 10 マス分だけ描く（回転すると四隅が欠けるため、丸くクリップする）。拡大図は階全体を描き、回転で欠ける分は余白を取る |
| 階の表示 | 拡大図の見出しに階名（現行どおり）。移動先の印は行き先の階名を添える（7 章） |

### 実装箇所

- クライアント `it()`（脱出図の描画）：回転と扇形の追加。`x.movementYaw`（＝`corridorHeading`）を渡す
- `_t()`（お札モードの図）は同じ関数に統合してよい
- 小図 `Me`（200×210）は丸くクリップして中心固定に

### 確認

- 通路を進んでいるとき、図の上が常に進行方向。角を曲がると図が回る
- `Q` で反転すると、図も 180° 回って、来た道が上になる
- 後方確認中は扇形（カメラ）と三角形（身体）が逆を向く
- 「北固定」に切り替えると現行と同じ向きで、隅に「N」が出る

## 7. 施設図の印に名前を付ける

### 現状

拡大図に描かれているもの：

| 印 | 意味 | 説明 |
|---|---|---|
| 黄の四角 6px | 未完了の作業場所（梯子・柱・暗号錠・鍵扉） | **無し** |
| 緑の四角 6px | 完了した作業場所 | 無し |
| 水色の縦棒 4×8px | 階段・梯子・地下への入口 | 無し |
| 円 3px ＋ 1 文字（清／メ／梯／バ） | 清めの石／メモ／梯子／バール | 1 文字のみ |
| 灰の点 | 見えている仲間 | 無し |
| 黄白の点 | 自分 | 無し |

図の下の凡例は「■ 作業場所 / ▮ 階段」の 1 行だけで、お札モードの名残。**柱が 3 本あるのに、どの四角が柱で、どれが暗号錠か分からない。**
拡大図は 276×276px 固定で、文字を置く余地がない。

### 仕様

**拡大図（`M`）**

| 項目 | 変更後 |
|---|---|
| 大きさ | 画面の **min(80vw, 80vh)** の正方形。階の全体と文字が入る |
| 名前 | **すべての印に名前**を添える。位置は印の右、11px、白文字＋黒縁取り。重なるときは下へずらす |
| 作業場所の名前 | `F`（任務）の `name` を短縮したもの＋進捗：「梯子を掛ける 未」「崩れた柱 34％」「暗号錠 済」「鍵扉 未」。柱は 3 本を「柱 1」「柱 2」「柱 3」と区別 |
| 移動先の名前 | `P`（移動先）の `name`：「梯子で 2 階へ」「1 階へ戻る」「地下へ」「地上へ」。**行き先の階名**を小さく添える |
| 道具・メモ | 「清めの石」「メモ 1」「メモ 2」「梯子」「バール」（メモは `order` 番号つき。拾っていないものは「メモ ?」） |
| 出口 | 「出口」。地上でのみ |
| 仲間 | 見えている仲間に**名前（魚）**：「ナギ（フグ）」。呪い中は名前を赤く |
| 自分 | 「あなた」＋扇形（6 章） |
| 形 | 種類で形を分ける：■ 作業場所、◆ 道具、● メモ、▲ 移動先（上向き＝上へ、下向き＝下へ）、★ 清めの石、═ 出口。大きさは **10px** |
| 状態 | 完了した作業場所は灰色＋「済」。未発見のものは描かない（現行どおり） |
| 凡例 | 図の下に形と名前の一覧を 1 行で。「■ 作業場所 ◆ 道具 ● メモ ▲ 階段・梯子 ★ 清めの石 ═ 出口 ⌂ あなた」。現行の「■ 作業場所 / ▮ 階段」を置き換える |
| 見出し | 「第七排水施設 ─ 1階・閉ざされた受付」＋「北固定」切替（6 章） |
| 開いている間 | 試合は進む（現行どおり）。**閉じるまで 3D は背景に見えたまま**（図を半透明にして、後ろに人影が動くのが分かる） |

**小図（右上）**

- 名前は出さない。形と色だけ。**触る（クリック／タップ）と拡大図が開く**（現行どおり）
- 自分から 10 マス以内の印だけ描く

### 実装箇所

- クライアント `it()`：ラベル描画の追加。名前の元データは `escape-map` の `F[].name`・`P[].name`・`missions.objects[].kind/order`・`party[].name/fish`
- `index.html` の `#map-panel`：canvas のサイズ指定を CSS に移し、凡例の `<p>` を差し替え
- 柱の番号は `F` の `spots` の順序で固定（1・2・3）

### 確認

- 拡大図を開くと、見えている印すべてに名前が付き、凡例に無い形が無い
- 柱 3 本がそれぞれ「柱 1〜3」と進捗つきで区別できる
- 「梯子で 2 階へ」の印に「2階・崩落した管理棟」が添えられている
- 文字同士が重ならない（重なる配置を作って確認：暗号錠と柱 1 が近い 2 階の左）
- 小図には文字が出ない
