# ドッペル鬼ごっこ（仮） — 企画レビューと制作計画

3〜6人が廃墟／洞窟に閉じ込められ、日付が変わるまで生き延びる 3D リアルタイム逃走探索ゲームの
企画に対する、成立性レビュー・設計提案・技術計画をまとめたドキュメント群。

| ファイル | 内容 |
| --- | --- |
| [DESIGN.md](DESIGN.md) | ゲームデザインの成立性レビュー、危険な穴、推奨する仕様変更、コアループの再設計案 |
| [TECH_PLAN.md](TECH_PLAN.md) | 技術スタック選定、ネットワーク設計、実装難所と回避策、MVP ロードマップ |

## 結論だけ先に

- **実装は可能。** ただし個人〜少人数でやるなら「AI ドッペル」ではなく **人間プレイヤーが操作する
  非対称 PvP** にすること。挙動 AI の作り込みが最大のコストであり、そこを人間に肩代わりさせると
  難所の 7 割が消える。
- **ゲームとして最も強い部分**は「肩を掴む」が攻撃でもあり撃退でもある、という**対称メカニクス**。
  背後の取り合いという一本の軸だけで駆け引きが立つ。ここを守ることが企画の生命線。
- **最も危険な部分**は「1 人死んだら全員ゲームオーバー」と「ドッペルが定期的に別人に変わる」の
  2 点。前者は試合が一瞬で終わって報われず、後者は推理の蓄積を無効化する。どちらも
  DESIGN.md で代案を出している。
- **視界の制約がすべてを決める。** 首が自由に 180 度回る一人称視点にすると「背後を取る」という
  企画の核が消滅する。三人称肩越し＋振り向きに時間がかかる操作系が必須。
